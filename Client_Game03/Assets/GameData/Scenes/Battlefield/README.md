# Воспроизведение боя

`BattlefieldSceneInitializator` создаёт представление, получает серверный лог и ожидает
`BattlefieldLogPlayer.PlayAsync`. Собственного `Update` для анимаций нет. DOTween
интерполирует значения в Unity PlayerLoop; `await` возобновляется по callback
завершения tween, без циклов с `Yield`, `NextFrame` или `Task.Delay`.

## DOTween

В `Assets/Plugins/Demigiant/DOTween` установлен официальный бесплатный DOTween
**1.3.030** из [архива Demigiant](https://dotween.demigiant.com/download.php).
Сохранены исходные файлы пакета и GUID. `DOTween.Modules.asmdef` позволяет использовать
модули из сборок проекта. Определение `DOTWEEN` добавлено штатным импортёром пакета.
Платный DOTween Pro не нужен.

`BattlefieldAnimationPlayer` объединяет DOTween и существующий UniTask через
`OnComplete`/`OnKill`. Символ `UNITASK_DOTWEEN_SUPPORT` для этой реализации не нужен.
Игровые анимации принадлежат отдельному проигрывателю: изменение скорости и
освобождение сцены не затрагивают чужие tween или `Time.timeScale`.

## Порядок и расширение лога

Лог копируется и сортируется по фактическому `index`. Индексы могут иметь пропуски
или начинаться с нуля; повторы и пустые записи отвергаются до воспроизведения.

- `RegisterRecord<T>` добавляет асинхронный обработчик типа записи.
- `RegisterAbility` добавляет анимацию способности. Она вызывает и **ожидает**
  переданный `impact(token)` в момент попадания, затем ожидает своё завершение.
- `RegisterImpactEffect<T>` указывает `indexReason` немедленного последствия.
  Последовательные связанные последствия, в том числе цепочки причин, запускаются
  при попадании и не проигрываются второй раз.
- Группа попадания заканчивается на первом несвязанном, отложенном или другом
  событии. Периодический урон не переносится из будущего к исходной способности.
- Для неизвестного значения способности отображаются известные последствия и
  выводится предупреждение. Неизвестный зарегистрированный в DTO тип события без
  клиентского обработчика пропускается с предупреждением.

Новый тип JSON-записи сначала нужно добавить в общий DTO/полиморфный сериализатор:
проигрыватель работает с уже десериализованными объектами и не может восстановить
неизвестный серверный формат. Новый обработчик подключается при настройке
проигрывателя в `StartAsync`, без изменения его основного цикла. Семантику ещё не
существующих механик проигрыватель не угадывает.

## Анимации и жизненный цикл

Атака сохраняет увеличение за 0,3 с, прежнюю кривую рывка
`1 - (1 - 1.2t)^6`, порог попадания в одну ширину карточки, возврат за 0,4 с
и паузу 0,5 с. Момент остановки рывка вычисляется один раз аналитически;
кривая передаётся DOTween как ease. Отличие от прежней проверки порога раз в кадр
ограничено её дискретностью.

Здоровье, очки действия и статистика меняются при показе соответствующей записи.
Смерть длится 2 с, разлёт чисел — 3 с при скорости ×1. Эти последствия выполняются
параллельно со следующими действиями; завершения всех запущенных операций сцена
дожидается в конце лога. Масштаб смерти и увеличение при атаке не перезаписывают
друг друга. Объекты чисел возвращаются в пул и при завершении, и при отмене.

Скорости ×1/×2/×5/×10 изменяют уже активные анимации и паузы. При отключении сцены
отменяются запрос и ожидания, tween уничтожаются без принудительного попадания.
Изменение разрешения обрабатывается перед отрисовкой Canvas и не сбрасывает
положение атаки или масштаб смерти. Числа используют координаты Canvas без
повторного применения коэффициента разрешения.

## Проверка

EditMode-набор `Assets.GameData.Scenes.Battlefield.Tests.BattlefieldPlaybackTests`
проверяет полный файл `TestData/пример лога.txt`, порядок и однократность обработки,
ожидание попадания/возврата, неизвестную способность, отложенный урон, пустой лог,
дубли индексов, статистику, скорость и отмену DOTween.

Для визуальной проверки в Play Mode открыть бой из обычного игрового сценария,
переключить все скорости во время рывка, изменить размер окна и выйти со сцены
при активных числах/смерти. Сам файл примера содержит только события и не заменяет
начальный снимок героев, который поступает в `spawnedBattlefield`.
